# AI Product Image Project (NEW)

Автоматизация AI-обработки изображений для WooCommerce.

- Детекция и удаление логотипов/водяных знаков
- Восстановление изображения (inpainting)
- Удаление фона
- Постобработка и компоновка на шаблон
- Интеграция с WordPress/WooCommerce

## Структура
- `plugins/ai-product-image/` — WordPress-плагин
- `uploads/ai_image/` — задания, результаты, шаблоны, логи
- `py/` — Python-скрипты
- `dataset/` — датасеты для обучения/валидации
- `lama-local/` — inpainting-модель LaMa

Подробности — в файле ai-image-project-context.md 

## Важно: весовой файл U^2-Net
Для работы автоматического выделения маски объекта требуется файл весов `py/u2net.pth` (размер ~170 МБ).

Скачайте его вручную с официального репозитория: https://github.com/xuebinqin/U-2-Net/releases

Поместите файл в папку `py/` рядом с кодом. 

## Важно: доступен только метод RunwayML
В текущей версии доступен только метод удаления логотипа через RunwayML (облачный AI). Для активации других методов (OpenCV, Lama Cleaner) раскомментируйте соответствующие строки в коде плагина и Python-скриптов и доработайте интеграцию. 

## Важно: версия Python и окружение

Вся работа с Python-скриптами (запуск, установка зависимостей, тестирование) должна осуществляться только в окружении Python 3.9, созданном в папке venv39. Использование других версий Python не поддерживается и приведёт к ошибкам.

Для активации окружения (Windows PowerShell):

```
.\venv39\Scripts\Activate.ps1
```

Для установки зависимостей:

```
pip install -r py/requirements.txt
``` 

## Контроль статусов и автоматизация

- Для каждого товара используется метаполе `_ai_image_status` (статусы: queued, task_created, processing, processed, applied, error) и `_ai_image_error` (текст ошибки).
- Повторная обработка возможна только вручную (кнопка "Повторить обработку").
- После создания задачи статус: `task_created`. После старта обработки (Python) — `processing` (через REST API). После результата — `processed`. После применения изображения — `applied`. Ошибки фиксируются в статусе и тексте.
- В админке отображаются статусы, ошибки, кнопки "Сбросить статус" и "Повторить обработку". Для каждой задачи доступен просмотр логов.
- Массовая обработка поддерживает фильтрацию по статусу (чекбоксы).
- Вся логика вынесена в отдельные классы (`AI_Product_Image_Product_Helper`, `AI_Product_Image_Task_Manager`).
- Реализован REST API endpoint `/wp-json/ai-image/v1/set-processing` для смены статуса на `processing` из Python-скрипта (секретный ключ настраивается в админке и config.yaml).
- WP Cron автоматически:
  - Запускает обработку товаров со статусом `queued` и `error`.
  - Контролирует зависшие задачи (`processing` > 30 мин → `error`).
  - Обновляет статусы и результаты.

### Инструкция по REST API для Python
- POST-запрос на `/wp-json/ai-image/v1/set-processing` с JSON: `{ "task_id": "...", "secret": "..." }`
- Секретный ключ задаётся в настройках плагина и в config.yaml (`wp_api_secret`).
- Вызов осуществляется в начале обработки задачи.

### Документация по статусам
- `queued` — задача ожидает обработки
- `task_created` — задача создана и помещена в очередь
- `processing` — задача в обработке (Python)
- `processed` — результат получен, изображение готово
- `applied` — изображение применено к товару
- `error` — ошибка обработки (текст ошибки в `_ai_image_error`)

### UI
- Вся информация о статусах, ошибках, логах и действиях доступна в админке на странице задач.
- Массовая обработка: фильтрация по статусу, запуск для выбранных товаров.

## Инструкция по развертыванию на боевом хостинге WordPress

### 1. Подготовка окружения

1. **Требования к серверу:**
   - WordPress 5.8+ и WooCommerce 5.0+
   - Python 3.9 (строго!)
   - Доступ к SSH/FTP и базе данных
   - Достаточно места для хранения изображений и логов
   - Возможность запускать cron-задачи (WP Cron или системный cron)

2. **Структура сайта:**
   - Корень WordPress: `/var/www/html/` (или аналогичная директория)
   - Папка плагинов: `/wp-content/plugins/`
   - Папка загрузок: `/wp-content/uploads/`

### 2. Установка WordPress-плагина

1. Скопируйте папку `plugins/ai-product-image/` в директорию `wp-content/plugins/` вашего сайта.
2. Активируйте плагин через админку WordPress (Плагины → Активировать).
3. После активации появится раздел управления задачами и настройками AI-обработки.

### 3. Размещение директорий для обмена и хранения

1. В папке `wp-content/uploads/` создайте структуру:
   - `ai_image/tasks/` — задания на обработку
   - `ai_image/results/` — результаты обработки
   - `ai_image/originals/` — оригиналы изображений
   - `ai_image/processed/` — финальные изображения
   - `ai_image/temp/` — временные файлы
   - `ai_image/templates/` — шаблоны фонов
   - `ai_image/logs/` — логи
   - `ai_image/archive/` — архивные задания и результаты
   - `ai_image/config/` — конфиги

2. Проверьте права доступа: веб-сервер и Python должны иметь права на чтение/запись во всех этих папках.

### 4. Установка и настройка Python-окружения

1. Скопируйте папку `py/` в корень проекта или отдельную директорию на сервере.
2. Войдите на сервер по SSH и перейдите в папку `py/`:
   ```
   cd /path/to/py
   ```
3. Создайте виртуальное окружение Python 3.9 (если не создано):
   ```
   python3.9 -m venv ../venv39
   ```
4. Активируйте окружение:
   - Для PowerShell (Windows):
     ```
     ..\venv39\Scripts\Activate.ps1
     ```
   - Для bash (Linux):
     ```
     source ../venv39/bin/activate
     ```
5. Установите зависимости:
   ```
   pip install -r requirements.txt
   ```
6. Проверьте наличие файла весов U^2-Net (`u2net.pth`) в папке `py/`.

### 5. Настройка конфигов и переменных окружения

1. Отредактируйте файл `py/config.yaml`:
   - Укажите пути к папкам, параметры обработки, секретные ключи, настройки логирования.
   - Проверьте, чтобы `wp_api_secret` совпадал с ключом в настройках плагина WordPress.
2. (Рекомендуется) Используйте отдельные конфиги для продакшена (например, `config_production.yaml`).
3. Не храните секретные ключи в публичных репозиториях!

### 6. Настройка WP Cron или системного cron

1. Включите автоматическую обработку в настройках плагина (чекбокс).
2. Задайте интервал, категорию и лимит товаров для обработки.
3. Если WP Cron не работает стабильно, настройте системный cron на вызов:
   ```
   wget -q -O - https://your-site.com/wp-cron.php?doing_wp_cron > /dev/null 2>&1
   ```
   или используйте планировщик задач хостинга.

### 7. Запуск и тестирование

1. Проверьте работу плагина через админку WordPress:
   - Создайте тестовую задачу, проверьте статусы, логи, результат.
   - Проверьте массовую обработку и автоматизацию.
2. Запустите Python-скрипт вручную для теста:
   ```
   python ai_image_processor.py
   ```
3. Проверьте логи и результаты в папках `uploads/ai_image/`.

### 8. Мониторинг и обслуживание

1. Используйте вкладку "Мониторинг" в админке для отслеживания статусов, ошибок, алертов.
2. Регулярно проверяйте логи и место на диске.
3. Настройте резервное копирование папки `uploads/ai_image/` и базы данных WordPress.
4. Для очистки временных файлов и логов используйте скрипт `py/cleanup_production.py` (можно запускать по cron).

### 9. Восстановление и поддержка

1. В случае сбоя используйте оригиналы из `originals/` для восстановления товаров.
2. Для ручного сброса статусов и повторной обработки используйте кнопки в админке.
3. Все параметры и инструкции по восстановлению описаны в документации и файле `state/plugin_status.md`.
