# Аудит и статус готовности плагина WordPress (ai-product-image)

---

## 1. Аудит текущего кода плагина

### 1.1. Основные файлы и классы

- ai-product-image.php — основной загрузчик плагина, подключает остальные модули.
- admin/admin-page.php — страница настроек и управления задачами в админке.
- includes/class-plugin.php — основной класс плагина (инициализация, хуки).
- includes/class-settings.php — регистрация и обработка настроек.
- includes/class-task-manager.php — создание, валидация, сохранение задач, обработка результатов.
- includes/class-product-helper.php — вспомогательные функции для работы с товарами WooCommerce (частично реализовано).
- includes/class-cron.php — заготовка для автоматизации (WP Cron).
- includes/class-logger.php — логирование (базовое).
- assets/ — стили и js для админки.

---

### 1.2. Реализованная функциональность

#### 1.2.1. Формирование задач на обработку изображений
- Реализовано частично: можно создать задачу для товара вручную или массово (через админку). Для каждого товара формируется JSON с параметрами: путь к оригиналу, шаблону, данные о товаре, путь для результата. Интеграция с WooCommerce: извлекаются атрибуты товара (бренд, модель, размеры и т.д.). Не реализовано: полноценная массовая обработка по фильтрам, гибкая очередь, advanced batch.

#### 1.2.2. Сохранение и структура данных
- Реализовано: задачи сохраняются в uploads/ai_image/tasks/ в формате JSON. Результаты обработки — в uploads/ai_image/results/. Оригиналы и шаблоны — в соответствующих папках. Логи — в uploads/ai_image/logs/.

#### 1.2.3. Настройки плагина
- Реализовано частично: настройки фонов (background_summer, background_winter, background_allseason), шрифтов, цветов, размеров, API-ключ RunwayML, debug-логирования. Не реализовано: настройка параметров обработки (batch size, advanced параметры), полноценная интеграция с WP Cron через UI, advanced права доступа.

#### 1.2.4. UI и админка
- Реализовано частично: страница управления задачами (очередь, ручной запуск, массовая обработка), страница настроек. Не реализовано: просмотр результатов прямо в админке, advanced фильтры, полноценный дашборд.

#### 1.2.5. Автоматизация (WP Cron)
- Не реализовано: только заготовка класса, нет реального расписания и автоматического запуска обработки.

#### 1.2.6. Валидация, безопасность
- Реализовано частично: проверка nonce при создании задач, проверка прав доступа к админке. Не реализовано: CSRF для всех действий, расширенная валидация данных, логирование действий пользователей.

#### 1.2.7. Мониторинг и логирование
- Реализовано частично: логирование операций (базовое). Не реализовано: дашборд мониторинга, алерты, advanced ротация логов.

## 6. Конкретные шаги по доработке плагина

### 1. Контроль статусов обработки и защита от повторных обработок

**Реализовано полностью:**

- Для каждого товара используется метаполе `_ai_image_status` (этапы: queued, task_created, processing, processed, applied, error) и `_ai_image_error` (текст ошибки).
- Перед созданием задачи статус проверяется, повторная обработка возможна только вручную (кнопка "Повторить обработку").
- После создания задачи статус: `task_created`. После старта обработки (Python) — `processing` (через REST API). После результата — `processed`. После применения изображения — `applied`. Ошибки фиксируются в статусе и тексте.
- В админке отображаются статусы, ошибки, кнопки "Сбросить статус" и "Повторить обработку". Для каждой задачи доступен просмотр логов.
- Массовая обработка поддерживает фильтрацию по статусу (чекбоксы).
- Вся логика вынесена в отдельные классы (`AI_Product_Image_Product_Helper`, `AI_Product_Image_Task_Manager`).
- Реализован REST API endpoint `/wp-json/ai-image/v1/set-processing` для смены статуса на `processing` из Python-скрипта (секретный ключ настраивается в админке и config.yaml).
- WP Cron автоматически:
  - Запускает обработку товаров со статусом `queued` и `error`.
  - Контролирует зависшие задачи (`processing` > 30 мин → `error`).
  - Обновляет статусы и результаты.

**Инструкция по REST API для Python:**
- POST-запрос на `/wp-json/ai-image/v1/set-processing` с JSON: `{ "task_id": "...", "secret": "..." }`
- Секретный ключ задаётся в настройках плагина и в config.yaml (`wp_api_secret`).
- Вызов осуществляется в начале обработки задачи.

**Автоматизация (WP Cron):**
- Включается в настройках плагина (чекбокс).
- Интервал задаётся в минутах.
- Работает полностью автономно: обработка очереди, контроль зависших задач, обновление статусов.

**Документация по статусам:**
- `queued` — задача ожидает обработки
- `task_created` — задача создана и помещена в очередь
- `processing` — задача в обработке (Python)
- `processed` — результат получен, изображение готово
- `applied` — изображение применено к товару
- `error` — ошибка обработки (текст ошибки в `_ai_image_error`)

**UI:**
- Вся информация о статусах, ошибках, логах и действиях доступна в админке на странице задач.

### 2. Контроль ошибок и доведение до успешного результата

**Реализовано полностью:**

- Ошибки логируются на каждом этапе (создание задачи, обработка, применение результата), текст ошибки сохраняется в `_ai_image_error` и доступен в админке.
- При ошибке статус задачи автоматически переводится в `error`, подробное описание сохраняется.
- В админке реализована кнопка "Повторить обработку" (сброс статуса на `queued` и повторный запуск).
- WP Cron автоматически контролирует зависшие задачи: если задача в статусе `processing` более 30 минут — переводит её в `error` с пометкой "таймаут".

### 3. Доработка автоматической замены изображения товара

**Реализовано полностью:**

- После успешной AI-обработки (статус `processed`) изображение товара автоматически заменяется на новое (из папки processed/), статус задачи меняется на `applied`.
- Все действия по замене изображения и смене статусов логируются (через class-logger.php).
- В случае ошибки при замене статус задачи становится `error`, подробное описание сохраняется в `_ai_image_error`, выполняется откат к предыдущему изображению.
- В админке отображается текущий статус применения изображения и возможные ошибки.
- Вся логика централизована в классе `AI_Product_Image_Product_Helper` и вызывается из обработчика результатов.

### 4. UI и админка

**Реализовано полностью:**

- Единая страница управления задачами с фильтрами по статусу, поиском по Task ID и ID товара, пагинацией, массовыми действиями (повторная обработка, сброс статуса, удаление).
- Визуальные индикаторы статусов и ошибок (цветовые метки, иконки, всплывающие подсказки).
- Просмотр результата и логов по каждой задаче в модальных окнах, кнопка "Скачать результат".
- Массовая обработка с возможностью указания ID категории (с учетом дочерних), лимита товаров и фильтрации по статусу.
- Страница настроек с параметрами генерации, API-ключами, настройками автоматической обработки по крону (ID категории, лимит, интервал).
- Вкладка "Мониторинг" (дашборд) с наглядной статистикой по статусам задач, алертами по ошибкам и зависшим задачам.
- Удобная навигация между задачами, массовой обработкой, настройками и мониторингом.

### 5. WP Cron и автоматизация

**Реализовано полностью:**

- Автоматический запуск массовой обработки изображений товаров по расписанию реализован через WP Cron и происходит только при включённом чекбоксе в настройках плагина.
- Интервал, ID категории и лимит товаров для автоматической обработки настраиваются через админку.
- Контроль зависших задач: если задача в статусе processing более 30 минут — переводится в error с пометкой "таймаут".
- Повторные попытки обработки для задач со статусом queued и error.
- После обработки статусы и результаты обновляются автоматически.
- Вся логика WP Cron централизована в отдельном классе и не запускается без разрешения администратора.

### 6. Конкретные изменения по файлам
- includes/class-task-manager.php: логика статусов, обновление метаполей, обработка ошибок.
- includes/class-product-helper.php: функции для работы с метаполями статуса, автоматическая замена изображения.
- admin/admin-page.php: UI для отображения статусов, логов, кнопки управления.
- includes/class-cron.php: задачи для WP Cron (обработка очереди, контроль зависших задач).
- class-logger.php: расширить логирование ошибок и действий.
